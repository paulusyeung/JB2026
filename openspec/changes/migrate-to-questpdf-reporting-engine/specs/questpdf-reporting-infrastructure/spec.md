## ADDED Requirements

### Requirement: QuestPDF SHALL be the designated PDF rendering engine
The system SHALL use QuestPDF as the PDF rendering engine for all reports generated by the modern API. All new reports SHALL use QuestPDF's declarative C# DSL for layout composition.

#### Scenario: New report uses QuestPDF
- **WHEN** a developer creates a new report endpoint
- **THEN** the report SHALL use QuestPDF's `IDocument` interface for rendering
- **THEN** the report SHALL NOT contain hand-rolled PDF object construction

### Requirement: Shared reporting library SHALL provide common building blocks
The system SHALL provide a shared `JB2026.Reporting` library containing reusable components for report generation including font registry, page layout conventions, and table components.

#### Scenario: Report uses shared components
- **WHEN** a developer creates a new report
- **THEN** the report SHALL reference the `JB2026.Reporting` library
- **THEN** the report SHALL use shared font registry for text rendering
- **THEN** the report SHALL use shared page layout conventions (A4, margins, headers/footers)

### Requirement: Each report SHALL define its own document type
Every report SHALL have a dedicated `IDocument` implementation that encapsulates its layout logic. Reports SHALL NOT share document definitions.

#### Scenario: Stock report has dedicated document type
- **WHEN** the stock record print report is generated
- **THEN** a dedicated `StockPrintDocument` class SHALL implement `IDocument`
- **THEN** the document SHALL receive the composed data model as a constructor parameter

### Requirement: Report rendering SHALL be testable without full PDF generation
The reporting infrastructure SHALL support unit testing of document structure and content without generating complete PDF bytes.

#### Scenario: Unit test validates document structure
- **WHEN** a developer writes a unit test for a report
- **THEN** the test SHALL be able to verify document metadata (title, author)
- **THEN** the test SHALL be able to verify page count and content presence
- **THEN** the test SHALL NOT require parsing generated PDF bytes

### Requirement: Font registry SHALL initialize at application startup
The system SHALL register all required embedded TTF fonts (Latin + CJK) at application startup before any report generation occurs. QuestPDF requires explicit font registration via embedded TTF/OTF files — PostScript Type 1 font names (e.g., "Helvetica") are not supported.

#### Scenario: Fonts available at startup
- **WHEN** the application starts
- **THEN** the font registry SHALL register an embedded Latin TTF font (e.g., Lato, Inter, or equivalent open-source Helvetica alternative)
- **THEN** the font registry SHALL register an embedded CJK TTF font (Noto Sans SC)
- **THEN** the QuestPDF community license SHALL be configured (`LicenseType.Community`)
- **THEN** report generation SHALL be able to use registered fonts immediately
